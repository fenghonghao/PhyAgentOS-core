PIPER 单臂 skill：策略与接口

比赛工位：一条 AgileX PIPER，桌后立杆上一台头部相机，手腕一台相机。模型只通过一个工具 robot.run(code) 控制机器人：它写一整段 Python，调用定位、看图、抓放这些通用能力，把一道题做完。三类题的做法写在 SKILL.md 的任务手册里，供模型参考和改写。

策略

模型现场写代码PyRUA-Lean

模型一次写一整段代码完成整题：定位、抓、放、检查都在同一段里，循环、分支、空抓重试也写在代码里。输出有问题就再写一小段修补，前面定义的变量和函数还在。

任务手册写成文字PyRUA-RSI 思路

三类题固定，经验写进 SKILL.md：计分要点、步骤、判断点和坑、参考代码。不做成函数：保密题和公开题同类不同细节，函数等于对公开题过拟合。参考代码是起点，模型按场景改。

看图交给 deepseek-flash

位置来自 SAM3 分割加深度（locate）；物体是什么、数字是几、朝哪边，问看图模型（look / inspect / orient）。小字用腕部相机逐个近拍、转正后拼成一张图问一次。

动作照着扣分规则设计

碰容器扣 50、碰其他物体扣 10，所以抓放都是竖直下降、竖直抬起；松手只再张开 1.5 cm；放进容器时在中心、物体底部高出沿口 3 cm 处松手，夹爪不进容器；目标越过挡板就拒绝移动。

没有超时停止

一场只在模型调用 forge_task_finalize 或裁判停机时结束。每次模型请求和 time_left() 都给出剩余秒数，只作参考。

经验由人工总结

11-04 每跑一道公开题，scene_digest.py 出一页摘要，据此更新手册，跑测试，重装；17:00 封存前冻结。PAOS 的自动 evolution 关掉，不让未审阅的内容写进 SKILL.md。

数据流

一场怎么跑

  1. 队员运行 ./run_scene.sh pub-1 "<题目>" [目标图像]：写入本场截止时间（SCENE_LIMIT_S，默认 180 s），启动 paos agent。
  2. 模型 activate_skill 读到 SKILL.md（接口 + 手册），forge_task_create 建任务。
  3. 模型按对应手册写一整段代码，forge_tool_start_action("robot.run", {"code": …}, wait=true) 执行，同一次调用拿回打印输出。
  4. 输出显示没完成就写修补段；完成后 forge_task_finalize。裁判看最终状态计分。
  5. 跑完 python3 dev/scene_digest.py，得到本场摘要，用来改手册。

任务怎么下发（是否给 PAOS 发自然语言、目标图像什么形式）、"完成信号"指什么，手册没写，明早先问组委会；现在的入口按"自然语言 + 图像路径交给 PAOS"准备。

接口（模型在 robot.run 里能用的名字）

单臂工位不写臂名：move_to([x, y, z])、set_gripper("open")、home()。世界坐标是机械臂底座系：x 向前、y 向左、z 向上，单位米；角度用度。业务结果作为返回值，硬件故障抛 RobotFault。

看

调用做什么要点
locate(text, near=None, …) → Sight按英文名词找一个物体并测量头部相机先看，必要时空夹爪把腕部相机移到物体上方复测；near 锁定某个实例；usable 为真才可抓
locate_all(text) → [Sight]一张头部图里列出所有实例用来数、比较、分类；抓之前由 pick 自动精测
look(question, marks=, image=, json=, zoom=)把当前相机画面发给看图模型提问marks 画编号圈；image 附目标图像；只用来认东西，位置不信模型
inspect(objects, question, json=)腕部相机逐个近拍，问一次每个物体一格、按块边转正；顺路精测，之后 pick 不用再飞
orient(objects, labels=) → [deg]印字的"上"朝哪个世界方向四个转向副本选正的一张，三次投票；labels 防 6/9 混淆
heading_of(direction, at, camera=)图像里的上下左右 → 世界朝向camera="tile" 用于转正后的格子

三份任务手册（SKILL.md 里，文字 + 参考代码）

A · 目标物品进容器

进容器 100，容器外 10 cm 内 50；碰其他物体 −10，碰容器 −50；多件取平均。
  1. 从目标图像和题目定出"哪件放哪个容器"，用相机里看到的英文名称；拿不准就画编号圈让模型配对。
  2. home()，空夹爪时先测所有容器。
  3. 每件 pick → place_in；放不进就放在容器边 10 cm 内拿一半分。
  4. 回位检查：物体在容器范围内，容器没动。
坑：夹爪绝不进容器；"object may not fit" 提示时仍对中松手。

B · 积木和水果分类

得分 = 初始散置件中归位的比例；最后检查所有积木和水果。
  1. locate_all 多个说法找全，look(marks=) 标积木/水果。
  2. 每类找成员最多的那一团，团外的就是散置件（通常 1–2 件）。
  3. 散置件放到本类旁边、背离另一类、离所有物体约 7 cm 的空位。
  4. 已归类的不动；最后重新列一遍。
坑：标错类会搬错，存疑就 inspect；起始就混在一起时，划两个区各搬少数。

C · 数字等式

3 个数字 + 1 个运算符 + 等号排成一行：结构 50，成立再 50。
  1. locate_all 找到 8 块，inspect 近拍读出每块；检查是否正好 3 个数字加 + − × ÷ = 各一个。
  2. 枚举成立的等式（÷ 要整除）。
  3. orient 五块的朝向。
  4. 沿 READ_RIGHT_DEG 选一条空的直线，按阅读顺序摆放，每块转到字头朝 READ_UP_DEG。
坑：+ 和 × 差 45°；"−" 竖过来像 1；6/9 颠倒。五块搬完占大半时间，先定好整行再动。

手册开头写明：参考代码是起点，按实际场景改写。参考代码原样在假世界里跑通（tests/test_skill_examples.py）。
